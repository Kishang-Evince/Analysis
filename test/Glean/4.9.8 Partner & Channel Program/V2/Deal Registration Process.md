# 4.9.8 Deal Registration Process — Independent Research Test Guide

**Purpose:** Verification of every claim in the companion research doc [V2/Deal Registration Process.md](../../../../Glean/Combined/4.9.8%20Partner%20&%20Channel%20Program/V2/Deal%20Registration%20Process.md). The core finding there is that the referral track is a hand-off model — Stratos would make the introduction and then Glean's own sales team runs everything from there — and that the "90-day protection window" figure used in this evaluation's own SOW methodology traces to generic industry guidance, not a confirmed Glean policy. This guide's job is to register a real test deal, time the actual eligibility response, and get the real protection-window number directly. Written so someone with no prior context on this project can pick it up and run it — mostly a real portal test and a partner-manager question, no developer access needed.

**Tenant entry:** Glean Partner Portal (post-approval) or the referral submission form · your Glean partner manager
**Companion research doc:** [V2/Deal Registration Process.md](../../../../Glean/Combined/4.9.8%20Partner%20&%20Channel%20Program/V2/Deal%20Registration%20Process.md)
**Base field doc (untouched, original):** [../Deal Registration Process.md](../../../../Glean/Combined/4.9.8%20Partner%20&%20Channel%20Program/Deal%20Registration%20Process.md) · **Section pre-flight:** [../Pre-Flight.md](../Pre-Flight.md)

**Prerequisites (what you need before starting):**
- Approved partner status and portal access (depends on the Partner Program Details field's application step).
- A real (or realistic test) opportunity to register.

**Sr No mapping:** Sr No 1-6 below map 1:1 to the same Sr No in the companion research doc's claims table [Combined/V2/Deal Registration Process.md](../../../../Glean/Combined/4.9.8%20Partner%20&%20Channel%20Program/V2/Deal%20Registration%20Process.md#claims-sr-no-1-6-mapped-to-test-guide) — same number, same claim, doc-sourced there / tenant-tested here.

**How to record a result:** For each row, write `Pass`, `Fail`, `Partial`, or `Blocked` in the Result column, plus one line in Notes on exactly what you found. "Pass" means you personally timed/confirmed it — not that the docs say so.

**Effort column:** each row lists an estimated time to complete plus a difficulty tag — `Easy` (a quick page check) or `Hard` (needs real portal access, a real test registration, or a written vendor answer) — so you can plan which rows to tackle first.
