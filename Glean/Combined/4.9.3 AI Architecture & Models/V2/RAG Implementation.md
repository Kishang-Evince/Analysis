## Headline

Yes, Glean uses Retrieval-Augmented Generation, and the architecture is genuinely agentic (plan → parallel search → ground → generate) rather than a single flat vector search. Glean does have a real passage-level "deep-linked" citation capability - but it is **beta, opt-in, and model-restricted**, not the default behavior; a normal chat request gets document-level citations only. The knowledge base itself is managed through a connector-pipeline architecture that supports both full and incremental crawls, with the indexing SDK handling batching, retries, and stale-document cleanup automatically. A broad but explicitly bounded set of document formats is supported for indexing - common office/text formats are covered, but structured data formats (JSON, XML), media, and archives are excluded by default. Vector chunking strategy specifically (chunk size, overlap, method) remains undisclosed anywhere found in the developer docs.

## Independent read

- Claims 1-2 are a genuine architectural strength: separating "decide what to retrieve" from "write the answer" into two different models is a more defensible RAG design than a single-pass system, and it's clearly documented, not just asserted. This is the field's clean, direct "yes" to "does the tool use RAG."
- Claims 3-7 are where accuracy really matters: marketing language around "precise, traceable citations" is true, but only under a specific, non-default configuration (Agentic Loop + GPT/Claude + enterprise-grounded content), and the capability itself is still beta. An evaluator who tests with a default `/chat` call and sees only document-level citations hasn't found a bug - they've found the actual default behavior, which is a materially weaker claim than the marketing implies.
- Claim 8 (chunking) is a straightforward, honest gap - it should be reported as "not disclosed," not implied to be either good or bad, since no evidence exists either way. This gap persisted even after this pass's fresh re-check specifically looking for it.
- Claims 9-10 are this pass's direct answers to the SOW's two added sub-questions. Claim 9 shows knowledge-base freshness is a real, structured mechanism (not a black box), while claim 10 shows format coverage is broad for standard business documents but explicitly excludes structured data and media by default - worth flagging to a healthcare client whose knowledge base may include scanned images or structured exports that would need separate handling.
