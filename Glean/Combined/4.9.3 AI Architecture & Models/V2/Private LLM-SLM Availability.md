## Headline

The answer splits sharply by *which layer of the product* you're looking at. **The Admin Console's Model Hub has no private/local/custom-endpoint option - it is a closed list of named commercial cloud providers only.** But **the developer-facing Agent Toolkit does support a genuinely private, on-premises model path**, via NVIDIA NIM microservices - just not reachable through the no-code Admin UI. On requirements and cost: the private path requires developer-level setup effort (a `base_url` override, plus standing up your own NIM infrastructure), and cost implications tie back to Glean's Enterprise Flex/FlexCredit model - higher-tier models consume more credits per run, while everyday basic/standard-model queries don't consume credits at all. On capability trade-offs: the closest documented "private-ish" default option (Customer Key/BYOK) trades away cross-cloud model access that the default Glean-managed Universal Key path retains.

## Independent read: why this needs a nuanced answer, not "Yes" or "No"

- If a client's requirement is *"can our business admins select a locally-run model from the standard Glean Model Hub screen"* - the answer is **No** (claim 1).
- If a client's requirement is *"can Glean technically connect to a model our engineering team runs on our own private infrastructure"* - the answer is **Yes, narrowly**, via one documented developer-level path (claims 3-4), not via the no-code admin surface.
- On cost and trade-offs specifically (the SOW's added emphasis): the *mechanics* of Glean's usage-based pricing (FlexCredits, tiered by model complexity) are documented (claim 7), but no source prices the NIM private path itself - that compute cost is the customer's own infrastructure bill, outside Glean's metering, and this project could not find a Glean-published estimate of what that infrastructure costs. The clearest documented trade-off (claim 8) belongs to the BYOK path, not the NIM path - a client asking specifically about NIM's trade-offs versus default should be told this remains an open question for direct sales conversation.
- This is exactly the kind of claim that would be dangerous to answer with a flat "Confirmed" or "Not Confirmed" - the correct entry for this field should state which layer of the product the capability lives in, and which sub-question (requirements vs. cost vs. trade-offs) has and hasn't been closed.
