## Headline

Yes, users can build fully custom agents - through two distinct surfaces with different constraints. The no-code **Agent Builder** lets anyone generate an agent from a natural-language description or configure it manually step-by-step, but stays within a fixed step/action vocabulary (no custom code step) and is bound by documented tool-call budgets and payload caps. For developers wanting real programmatic control, Glean explicitly supports building agents in third-party frameworks - **OpenAI, LangChain, Google ADK, CrewAI, and more** - plus its own Python agent toolkit, a Go API client, an Agents API (Beta), MCP server connectivity, and OpenAPI-based custom actions. The original narrower finding - no in-workflow code-authoring step exists in the visual canvas itself, and the headless builder is prompt-driven rather than code-driven - still holds and is reconfirmed below.

## Independent read

- Claim 1 is a genuinely useful clarification for setting expectations with a client's engineering team: "headless" here means file-based agent *configuration*, invoked via natural-language prompts, not a code-authoring SDK - a team expecting to write Python logic that becomes agent behavior would be disappointed by what this specific path offers, even though claim 7 shows a genuine code-first path exists elsewhere (third-party frameworks via the Agents API).
- Claim 2's honest "documentation is vague" framing is the right way to handle this - rather than guessing at Auto mode's sandbox capabilities from silence, this should be flagged as a real gap worth asking Glean about directly if a client's use case depends on knowing exactly what computation is possible there.
- Claims 5-7 together answer the SOW's actual question cleanly: yes, fully custom agents are buildable, via either a no-code canvas (with a fixed action vocabulary and documented budgets/caps) or a genuine multi-framework developer path (OpenAI, LangChain, Google ADK, CrewAI). The field should not be summarized as a flat "no custom code" finding - that was true only of the narrower original question about the visual canvas.
- Claim 8 is worth carrying into any client conversation as an open question: the marketing language "build in your language" is not backed by a published language-support matrix on the page checked this pass.
