## Headline

Glean's own architecture documentation splits data flow into three named, separately-documented stages - Data Ingestion Flow, Data Processing Flow, and Query Flow - but each page is written for security assurance, not implementation depth: none of the three discloses chunking, embedding, or vector-database specifics for its general document/search index. The one place Glean *does* publish real pipeline internals - AST-based chunking, embedding models, and an approximate-nearest-neighbor vector index - is a separate, code-search-specific architecture page, not the general document pipeline. Permission/ACL propagation is the best-documented stage of the four: crawlers pull content and its ACL together, and the Indexing API confirms permission/group-membership changes propagate **asynchronously**, with an explicit "small delay" before visibility updates take effect.

## Independent read

- The field maps cleanly onto Glean's own three-page architecture split (ingestion / processing / query), but "storage" and "output" as the SOW frames them are each only partially covered by Glean's own docs - storage gets one strong tenant-boundary sentence (Claim 5) and nothing on the mechanism; output gets routing/auth detail but nothing on retrieval-to-LLM mechanics (Claim 9).
- Claim 6 is the most interesting find of this pass: Glean *does* have a public, detailed, technically rich pipeline write-up (chunking → embedding → ANN vector index) - it's just scoped to code search, not the general document/enterprise-search index most buyers would assume "data flow architecture" means. Citing it as if it described the general pipeline would be a sourcing error worth avoiding in any client-facing summary.
- Claim 8's asynchronous-permission-propagation delay is the single most operationally relevant finding for a healthcare buyer: an unquantified "small delay" between a source-system permission change (e.g., an employee offboarded, a document restricted) and that change taking effect in Glean search is exactly the kind of gap that needs a real timed tenant test, not an assumption of near-real-time enforcement.
